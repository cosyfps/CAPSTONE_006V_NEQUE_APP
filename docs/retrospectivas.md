# Retrospectivas del proyecto

Durante el desarrollo de Ñeque se realizaron revisiones internas del avance con el objetivo de identificar dificultades, aprendizajes y oportunidades de mejora.

Estas revisiones permitieron evaluar tanto aspectos técnicos como de organización del equipo.

## Retrospectiva 1

### Qué funcionó bien

- Se logró definir la idea principal del producto.
- Se identificaron los principales tipos de usuario del sistema.
- Se establecieron las funcionalidades más importantes para entrenadores y alumnos.
- Se avanzó en la definición de la arquitectura tecnológica.

### Dificultades detectadas

- La organización de tareas no siempre fue constante.
- Algunas decisiones funcionales requirieron más tiempo de análisis.
- Existieron diferencias en los tiempos disponibles de los integrantes del equipo.

### Acciones de mejora

- Dividir las tareas en actividades más pequeñas.
- Definir responsables claros por cada tarea.
- Priorizar primero las funcionalidades esenciales del sistema.
- Mejorar la coordinación y seguimiento de avances.

## Retrospectiva 2

### Qué funcionó bien

- Se logró avanzar en la estructura técnica del proyecto.
- Se definieron con mayor claridad los flujos entre entrenador y alumno.
- El uso de control de versiones permitió mantener registro de los cambios realizados.

### Dificultades detectadas

- Algunas tareas tomaron más tiempo de lo esperado.
- Fue necesario revisar decisiones tomadas previamente.
- La documentación no avanzó al mismo ritmo que el desarrollo técnico.

### Acciones de mejora

- Actualizar la documentación junto con el desarrollo.
- Revisar periódicamente el estado de las tareas.
- Comunicar con anticipación los bloqueos o dificultades.
- Mantener prioridades claras para evitar dispersión.

## Retrospectiva 3

### Qué funcionó bien

- Se obtuvo una visión más clara del producto final.
- Se avanzó en la integración de las principales funcionalidades.
- Se identificaron mejoras necesarias antes de la entrega final.

### Dificultades detectadas

- Existieron retrasos respecto a algunos plazos planificados.
- Quedaron tareas de documentación pendientes para etapas finales.
- Fue necesario reorganizar prioridades para completar los entregables principales.

### Acciones de mejora

- Concentrar los esfuerzos en los entregables obligatorios.
- Evitar incorporar funcionalidades secundarias antes de cerrar las principales.
- Mantener un seguimiento frecuente del estado general del proyecto.
